## 승인 범위

[개발 및 운영안 검토 결과](261018-131800-개발-및-운영안-검토-결과.md)에 따라 Vercel 배포, 가비아 DNS 연결, OG 설정 및 브라우저 검증을 진행한다. 이후 사용자 지시에 따라 카카오톡 메시지는 발송하지 않으며, Android·iPhone 실기기 테스트는 후속 작업으로 남긴다.

## 구현

- `invitation/index.html`: 최초 HTML에 OG 제목·설명·운영 URL·이미지 정보를 포함했다.
- `invitation/public/og-image.jpg`: 1200×630 JPEG, 약 31KB의 교체 가능한 대체 이미지를 추가했다.
- `invitation/artwork/og-image.svg`: 대체 이미지의 편집 가능한 벡터 원본이다.
- `invitation/vercel.json`: Vite, `npm ci`, `npm run build && npm test`, 출력 경로 `dist/client`를 지정했다. Vercel 프로젝트 루트는 `invitation`이다.
- `invitation/tests/deployment/smoke.test.mjs`: 실제 HTTP 응답에서 OG 정보, JPEG 응답, 진입 스크립트와 선로딩 이미지를 확인한다.
- `invitation/AGENTS.md`: 공개 자료 전제, Vercel 운영 대상, 카카오톡 발송 금지 및 실기기 검증 보류 방침을 기록했다.

화면의 기존 이름·예식 일정·장소는 원본 재현용 예시다. OG는 이름과 날짜를 포함하지 않는 대체 문구를 사용한다. 실제 하객에게 안내하기 전 사용자가 본문과 예식 정보를 교체해야 한다.

### 배포 중 수정한 문제

첫 클라우드 빌드에서는 빌드 전 테스트 실행으로 `emits the files required by Sites packaging`이 실패했다. 기존 로컬 산출물 때문에 드러나지 않았던 순서 문제이며, 빌드 후 전체 테스트를 실행하도록 정정했다. 로컬 `dist`를 제거하고 다시 빌드·테스트하여 성공을 확인했으며, 이후 Vercel에서도 8개 테스트가 모두 통과했다. 테스트를 생략하거나 기존 Sites 테스트를 변경하지 않았다.

GitHub·가비아에서는 인증·저장 후 이전 화면에 로딩 표시가 남는 현상이 있었다. 새 탭 또는 새로고침으로 실제 인증과 저장이 완료된 상태를 확인했다. GitHub 인증 메일을 읽거나 인증코드를 수집할 필요는 없었다. Vercel 저장소 권한은 사용자 확인 후 청첩장 저장소만 추가됐으며 기존 저장소 권한은 유지됐다.

### 복구 기준

이번에 확인한 첫 정상 기능 배포 커밋은 `aa1bde1`이다. 이후 변경에서 문제가 발생하면 문제 커밋을 되돌려 `main`에 반영하거나 Vercel에서 정상 커밋을 재배포한다. 현재 정상 서비스를 되돌리는 실제 롤백 작업은 수행하지 않았다.

## 교체 및 재검증 방법

- OG 이미지: `invitation/public/og-image.jpg`를 교체한다. 크기를 바꾸면 `index.html`의 `og:image:width`와 `og:image:height`도 맞춘다.
- OG 설명: `invitation/index.html`의 `og:description`과 일반 `description`을 함께 수정한다.
- OG 제목: 같은 파일의 `og:title`과 `<title>`을 함께 수정한다.
- 예식 및 브런치 일정·장소: `invitation/src/content.js`의 일정 데이터와 `src/App.jsx`, `src/Hero.jsx`의 표시 문구를 함께 수정한다.
- 반영 후 카카오디벨로퍼스 URL 메타정보 도구에서 확인한다. 오래된 정보가 나오면 해당 URL의 캐시를 초기화하고 다시 조회한다.

배포 응답 검사는 `invitation` 디렉터리에서 실행한다.

```sh
BASE_URL=https://invitation.soowa.site npm run test:deployment
```
