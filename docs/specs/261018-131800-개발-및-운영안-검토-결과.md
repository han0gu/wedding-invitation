# 모바일 청첩장 개발 및 운영안 검토 결과

검토일: 2026-10-18

검토 범위는 [모바일 청첩장 생성 문서의 청첩장 개발 및 운영 섹션](../etc/모바일-청첩장-생성.md#청첩장-개발-및-운영)과 해당 내용에 대한 사용자 답변이다. 다른 작성 중인 섹션은 검토 대상에 포함하지 않는다.

현재 청첩장은 별도 애플리케이션 서버나 데이터베이스 없이 제공할 수 있는 React/Vite 정적 웹페이지다. **GitHub에 소스를 관리하고 Vercel Hobby로 배포하여 `https://invitation.soowa.site`로 제공하는 구성을 우선 권고한다.** Cloudflare Pages도 적합한 대안이다. 호스팅 서비스 선택은 권고안이며, 실제 배포가 완료되었다는 의미는 아니다.

## 1. 확정된 운영 전제

- 개인의 결혼식 청첩장으로 운영하며, 청첩장 판매 서비스로 확장할 계획은 없다.
- 소스 코드는 Public GitHub 저장소 <https://github.com/han0gu/wedding-invitation>에서 관리한다.
- Git으로 추적하는 자료는 모두 공개 가능한 것으로 판단한다. 공개에 부적절한 자료의 제외와 `.gitignore` 관리는 사용자가 담당한다.
- 이미 구매한 `soowa.site` 도메인의 서브도메인 `invitation.soowa.site`를 하객에게 안내한다.
- 혼주가 카카오톡으로 URL을 전달하고 하객이 카카오톡 인앱 브라우저에서 여는 경로를 주 이용 경로로 본다. 이는 예상 이용 방식이며 측정된 이용 비율은 아니다.
- Android Chrome, iPhone Safari, Desktop 브라우저도 지원하되 검증의 우선순위는 카카오톡 인앱 브라우저에 둔다.
- Open Graph는 대체 이미지와 문구로 먼저 구성하고, 이후 사용자가 이미지와 설명을 직접 교체할 수 있게 한다.

## 2. 배포 방식 검토

### 웹 호스팅

| 후보 | 적합성 및 운영 부담 | 검토 결과 |
| --- | --- | --- |
| Vercel Hobby | 현재 정적 웹페이지를 배포하기 적합하다. Git 연동 배포와 미리보기 환경을 이용할 수 있고, 사용자의 개인·비상업적 운영 목적은 Hobby의 용도 제한에 부합한다. | 우선 권고 |
| Cloudflare Pages | 정적 웹페이지에 적합하며, 외부 DNS를 유지하면서 사용자 지정 서브도메인을 연결할 수 있다. | 대안 |
| Mac mini + Docker 및 OSS | 구축은 가능하지만 전원, 절전, 재부팅, 인터넷 연결, 외부 접속 경로, HTTPS와 장애 복구를 직접 관리해야 한다. Docker만으로 이러한 운영 부담이 해소되지는 않는다. | 개발·미리보기 용도로 활용 권고 |

Vercel Hobby는 개인·비상업적 용도를 위한 무료 플랜이며 사용량 제한이 있다. 현재 목적에는 적합하지만 무료라는 이유로 무제한 제공이나 가용성 보장을 전제하지 않는다. [Vercel Hobby 공식 안내](https://vercel.com/docs/plans/hobby), [Vercel 플랜 안내](https://vercel.com/docs/plans)

### 백엔드

Supabase는 웹 호스팅 후보와 분리하여 데이터베이스·인증·저장소 등의 백엔드 후보로 분류한다. 현재 구현에는 필요하지 않으므로 초기 운영 구성에 추가하지 않는다. 향후 서버에 데이터를 저장하는 기능이 확정되면 해당 요구에 맞춰 별도로 검토한다.

Supabase를 추후 도입한다면 무료 프로젝트의 비활성 1주 후 일시중지 조건을 고려해야 한다. 이는 현재 정적 청첩장 운영에 적용되는 조건은 아니다. [Supabase 요금 안내](https://supabase.com/pricing)

## 3. 도메인 및 배포 구성

### 도메인 연결

원문에 기재된 가비아 네임서버를 유지하는 구성을 기본으로 한다.

- `ns.gabia.co.kr`
- `ns1.gabia.co.kr`
- `ns.gabia.net`

호스팅 프로젝트에 `invitation.soowa.site`를 사용자 지정 도메인으로 등록하고, 가비아 DNS 관리 화면에 해당 서비스가 안내하는 DNS 레코드를 설정한다. Vercel을 선택하는 경우 프로젝트에서 안내하는 실제 레코드 값에 따른다. [Vercel 도메인 연결 안내](https://vercel.com/docs/domains/working-with-domains/add-a-domain)

Cloudflare Pages를 선택하면 먼저 Pages 프로젝트에 사용자 지정 도메인을 등록한 뒤, `invitation`의 CNAME을 해당 프로젝트의 `<프로젝트>.pages.dev`로 설정한다. 이처럼 서브도메인만 연결하는 경우 도메인 전체의 네임서버를 Cloudflare로 변경할 필요는 없다. [Cloudflare Pages 도메인 연결 안내](https://developers.cloudflare.com/pages/configuration/custom-domains/)

도메인 연결 완료 기준은 DNS 레코드 저장 자체가 아니라, 외부 네트워크에서 `https://invitation.soowa.site`가 인증서 오류 없이 열리고 청첩장과 이미지가 정상 표시되는 것이다.

### 빌드 설정

현재 저장소 구조와 [Vite 설정](../../invitation/vite.config.mjs)을 기준으로 한다.

| 항목 | 설정 |
| --- | --- |
| 프로젝트 루트 | `invitation` |
| 의존성 설치 | `npm ci` |
| 빌드 및 검증 | `npm run build && npm test` |
| 정적 배포 디렉터리 | `dist/client` — 프로젝트 루트 기준 |
| 운영 브랜치 | `main` 사용 권고 |

현재 빌드는 Sites용 산출물도 생성하지만, 위 정적 호스팅 구성에서는 `dist/client`를 배포 대상으로 사용한다. 기존 빌드 및 Sites 관련 파일을 제거할 필요는 없다. 실제 배포 검증에서 Sites 테스트가 산출물을 필요로 하는 것을 확인하여, 실행 순서를 빌드 후 테스트로 정정했다. 두 단계가 모두 성공해야 배포한다.

### 수정 및 복구 절차

1. 변경 사항을 미리보기 배포에서 확인한다.
2. 테스트와 빌드가 성공하고 주요 동작을 확인한 변경 사항을 `main`에 반영하여 운영 배포한다.
3. 배포 후 실제 운영 URL에서 카카오톡 진입과 주요 화면을 확인한다.
4. 운영 문제가 발생하면 호스팅 서비스의 이전 정상 배포로 복구한다. 필요하면 원인 커밋을 되돌려 다시 배포한다.

운영 브랜치와 미리보기 브랜치는 호스팅 설정에서 구분한다. 테스트 실패 시에는 배포가 진행되지 않도록 빌드 명령을 설정한다.

## 4. 화면 제공 및 브라우저 검증

모든 기기에서 동일한 콘텐츠와 기능을 제공한다. 모바일에서는 화면 너비에 맞추고, Desktop에서는 최대 너비 440px의 청첩장을 중앙에 표시한다. 현재 구현의 모바일 중심 레이아웃을 유지하며 별도 Desktop 화면을 만들지 않는다.

카카오톡 인앱 브라우저는 Android와 iPhone에서 각각 실제 기기로 확인한다. Desktop 브라우저의 모바일 화면 모드 확인만으로 인앱 브라우저 검증을 대신하지 않는다.

| 우선순위 | 환경 | 검증 범위 |
| --- | --- | --- |
| 최우선 | Android 카카오톡 인앱 브라우저 | 실제 대화방 URL 진입, 첫 화면, 열기 동작과 애니메이션, 세로 스크롤, 버튼, 지도 링크, 일정 저장 동작 |
| 최우선 | iPhone 카카오톡 인앱 브라우저 | 위 항목과 함께 화면 높이 변화, 안전 영역, 외부 앱·브라우저 전환 및 복귀 |
| 보조 | Android Chrome, iPhone Safari | 화면 표시, 스크롤, 주요 버튼과 외부 링크, 일정 저장 |
| 보조 | Desktop 브라우저 | 중앙 정렬, 최대 너비, 마우스 조작과 스크롤, 주요 링크 |

로그인 없이 청첩장이 열리고, 애니메이션이나 외부 앱 연결 문제 때문에 예식 정보를 읽을 수 없는 상황이 없어야 한다. 인앱 브라우저에서 일정 저장 등 특정 동작이 제한되면 실제 확인된 제약에 맞춰 외부 브라우저 열기 안내 등 대체 경로를 제공한다. 구체적인 제약이나 우회 방법은 실기기 검증 후 확정한다.

## 5. 카카오톡 링크 미리보기와 Open Graph

현재 [HTML 진입 파일](../../invitation/index.html)에 Open Graph 메타태그가 없으므로 배포 준비 시 추가한다. 메타태그는 클라이언트 JavaScript 실행 후가 아니라 최초 HTML의 `<head>`에 포함한다.

초기 적용값은 다음과 같이 정한다. 아래는 적용 명세이며, 이 검토 문서 작성으로 HTML이나 이미지 파일이 변경되는 것은 아니다.

| 항목 | 초기 적용값 |
| --- | --- |
| `og:type` | `website` |
| `og:title` | `저희 결혼합니다` |
| `og:description` | `소중한 분들을 초대합니다. 저희의 시작을 함께 축복해 주세요.` |
| `og:url` | `https://invitation.soowa.site/` |
| `og:image` | `https://invitation.soowa.site/og-image.jpg` |
| `og:image:alt` | `저희 결혼합니다 — 모바일 청첩장` |

대체 이미지는 청첩장의 기존 색감과 장식을 활용한 가로형 JPEG로 준비한다. 제작 규격은 1200×630px를 기본으로 하되, 실제 카카오톡 미리보기의 잘림을 고려하여 핵심 문구를 중앙에 배치한다. 이름과 날짜는 확정 정보로 교체하기 전까지 넣지 않는다. 이 규격은 제작 기준이며 카카오톡의 필수 규격이라는 의미는 아니다.

사용자가 교체할 위치는 다음과 같이 단순하게 유지한다.

- 이미지: `invitation/public/og-image.jpg`를 교체한다. 배포 후 공개 경로는 `/og-image.jpg`가 된다.
- 설명: `invitation/index.html`의 `property="og:description"` 값을 수정한다. 일반 검색·브라우저 설명인 `name="description"`도 같은 문구로 맞춘다.
- 제목: 필요하면 같은 파일의 `og:title`과 `<title>`을 함께 수정한다.

`og-image`와 `og-description`에 대응하는 실제 메타 속성 이름은 각각 `og:image`, `og:description`이다. 이미지 URL은 외부에서 로그인 없이 접근할 수 있는 절대 HTTPS 주소로 설정한다.

공유 검증은 실제 운영 URL을 카카오톡 대화방에 붙여 넣어 제목·설명·이미지를 확인하는 방식으로 진행한다. OG 정보를 교체한 뒤 이전 내용이 보이면 카카오디벨로퍼스 도구에서 메타정보 캐시를 초기화하고 새로 공유하여 확인한다. 기존에 전송된 메시지 카드가 모두 즉시 바뀐다고 가정하지 않는다. [카카오디벨로퍼스 도구 안내](https://developers.kakao.com/docs/ko/tool/common)

## 6. 배포 전 확인 및 남은 결정

### 배포 전 확인

- 운영 URL의 HTTPS 접속과 이미지 로딩이 외부 네트워크에서 정상이다.
- Android와 iPhone의 카카오톡 인앱 브라우저에서 주요 흐름을 확인했다.
- Android Chrome, iPhone Safari, Desktop에서 기본 기능을 확인했다.
- 카카오톡에서 공유 제목·설명·대표 이미지가 의도대로 표시된다.
- 공개할 실제 예식 정보와 대체 문구의 교체 여부를 사용자가 확인했다.
- 운영 배포 설정과 이전 정상 배포로 복구하는 방법을 확인했다.

### 결정 시점

문서 작성 전에 추가로 결정해야 할 필수 사항은 없다. 실제 배포 시에는 우선 권고안인 Vercel Hobby를 사용할지 Cloudflare Pages를 사용할지 확정하고 해당 계정과 프로젝트를 연결하면 된다. 도메인 등록·DNS 변경·운영 배포는 이 문서 작성과 별도의 실행 단계다.

예식 이후의 공개 유지 기간은 아직 정하지 않았다. 임의의 종료일이나 자동 삭제 정책을 두지 않고, 운영 종료가 필요해질 때 사용자가 결정한다.
